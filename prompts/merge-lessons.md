# 把另一台电脑上的项目经验并回 skill

几台电脑同时做不同的游戏时，不用拷几 GB 的游戏工程回来。在那台电脑上让 agent 写一份 3–8 KB 的纯文本复盘
（外加零业务硬编码的通用小脚本，如果有），带回来并进 skill 即可。

## 第 1 步：在那台电脑上发给 AI

```text
请基于当前这个离线手游项目的文档、交接单、构建脚本和源码，提炼一份 5 KB 以内的纯文本复盘《project-lessons.md》，
用来合并进通用的离线复活 skill。只写可复用的工程经验，不贴大段日志和业务细节，不写游戏名、包名、服务器地址、密钥和本机路径。按 6 节输出：

1. 引擎 / 热更 / 协议形态和离线架构（为什么选这条路线，和包内拦截、内嵌服务相比的优缺点）
2. 解包 / 解密 / 去壳 / 校验绕过的关键发现（魔数、偏移、签名校验、SDK 去除）
3. 开发期快循环（热推 / 热加载、GM 档、日志裁判、怎么避免反复重打包）
4. 新踩的硬坑（现象 → 根因 → 以后怎么避开，尤其是模拟器、打包、冷启、存档）
5. 能直接抽出来复用的通用脚本清单（文件名、用途、有没有写死业务）
6. "如果重做一次，开局就该定好"的流程或预授权规则
```

## 第 2 步：带回来并进 skill

```text
这是另一台电脑上的项目复盘（见附件 / 粘贴内容），请合并进 offline-game-revival：
1. 新引擎架构补一份 references/route-*.md，并在 references/kickoff.md 的路线决策表里登记；
2. 新坑去重后写进 references/pitfalls/ 对应分文件的末尾（格式照抄），致命的同步进 references/red-lines.md 和 scripts/guard_hook.py；
3. 通用脚本放进 scripts/，做语法检查并实际跑一次；
4. 公开仓库那份要脱敏（不写游戏名、包名、地址、密钥、本机路径），然后提交。
```

## 第 3 步：几台电脑保持同一份

把 skill 放进自己的私有 Git 仓库，各台电脑 clone 到 agent 的 skills 目录（或插件目录），以后哪台有新经验就 `git push`，别的 `git pull`。
