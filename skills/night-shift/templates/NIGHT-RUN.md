# 夜间全自动运行指令（<项目名>）

> 用法：在本项目的 Claude Code 会话里输入
> `/loop 读 <状态目录>/NIGHT-RUN.md 并严格按它执行；每次醒来都重新读一遍它`
> 不给间隔，让 agent 自己定节奏。之后不用再管。
> 本文件是指令本身；`<状态目录>/NIGHT-PLAN.md`、`NIGHT-LOG.md`、`NIGHT-REPORT.md` 是它运行时写的状态文件。
>
> 填法：把所有 `<…>` 换成你项目的值；用不上的行整行删掉，不要留占位。

---

## 开跑前人做的事（每次挂机前过一遍，两分钟）

1. 权限模式是 auto（会话顶部能看到）。不是的话任何一次确认框都会把整晚卡死。
2. 主会话模型选 `<主模型>`（平时的主力模型，不用最贵那档：整晚体力活会把额度烧光，判断力的差距在这类活上体现不出来）。子代理：scout = `<便宜模型>`，worker = `<中档模型>`。
3. 测试设备 `<设备名>` 开着并在线（`<连接方式>`）；`<不许碰的设备>` 拔掉或关掉。
4. 电脑插电。防睡眠由 agent 自己调 keep-awake，但合盖、手动睡眠之类的动作要自己避免。
5. 项目是 git 仓库并且工作区干净；不是的话让 agent 在第一次醒来时自己 init（下面有规定）。
6. 今晚有例外（允许用某台设备、允许过了截止时间继续……）就写进文末「今晚的额外授权」，不要只在聊天里说。

---

## 给 agent 的指令（从这里开始是你要执行的）

你是本项目的夜间值班主 agent。用户已经离开，到 `<截止时间>` 之前不会回答任何问题，也不会看屏幕。你的目标：在不打扰用户、不做任何危险操作的前提下，把 `NIGHT-PLAN.md` 里的事项尽可能多地推进到「已在 `<设备名>` 上验证」。

### 每次醒来先做（按顺序，不跳过）

1. 读 `NIGHT-PLAN.md`（不存在就按下一节生成）和 `NIGHT-LOG.md` 最后 40 行，弄清上次做到哪。查有没有子会话（`list_sessions`，linked）、子代理或后台命令还在跑；超过 brief 里时限的停掉，LOG 记一行。不要重读 `<项目状态文档>` 全文，只读 PLAN 里引用的章节。
2. 调 `request_keep_awake`。
3. 调 `get_usage`。剩余额度低于 `<额度阈值，默认 15%>`：只做收尾（写报告、提交），然后停止循环。
4. 确认 `<设备名>` 在线（`<检查命令>`）。不在线就 `<拉起办法>`，等 90 秒再试；两次仍不在线，只做不需要设备的事项，并在 LOG 里记一行。
5. 本地时间已过 `<截止时间>`，并且「今晚的额外授权」里没有延长：直接进「停止」流程。

### 第一次醒来：建基线和计划

1. 项目不是 git 仓库时：`git init`，写 `.gitignore`（`<构建产物、大文件、缓存目录和后缀>`），做一次基线提交。之后每完成一项都提交。
2. LOG 第一行记：时间、额度（5 小时窗口和周额度）、git 基线哈希、用的设备、有没有子会话。
3. 从 `<项目状态文档>` 的状态段和 `<待办来源>` 生成 `NIGHT-PLAN.md`（格式见文末），每项一行：优先级、状态、做什么、完成标准（状态真的变了，且杀进程重启后仍正确）、涉及文件、验证方式。
4. 顺序：先验证「已写未验证」的，再做「未开始」里收益大、最独立的，依赖外部条件（`<例如需要联网、需要别人的数据>`）的放最后。排序依据：`<用户必经路径> > <日常循环> > <边角功能>`。
5. 计划生成后提交，LOG 里写一行「计划建立，共 N 项」。

### 执行规则

- **一次只开一个事项**，做到验证通过或判定阻塞再换下一个。PLAN 里同时只有一项是 in_progress。
- **分工**：大范围搜索、读日志找第一个异常、通读反编译产物 → scout；规格已经写清的实现、补测试用例、批量改表 → worker；你自己只做判断、定规格、收货、设备验证。几次工具调用能做完的小活自己做，不拆。
- **派活必须写全**：目标、背景（文件和行号）、范围（只许改哪些文件）、完成标准、交付格式、时限（「N 分钟内交，不开后台任务」）。收货时自己重跑测试、抽查 diff、确认没越界改文件；子代理说「已完成」不算数。
- **并行会话**：PLAN 里有两个以上互不依赖、文件不重叠的实现事项时，用 `start_session`（initiation 为 user_asked，这是用户在本文件里授权的）各开一个会话，fresh 上下文，每个只改自己模块的文件和自检脚本。同一时刻最多两个子会话。被应用拒绝就改用后台 worker 子代理，不重试。它们交回后由你做合并构建和设备验证。`<构建脚本、补丁主入口、存档结构>` 和 `<状态目录>/` 只有你能改。
- **验证标准**：证据必须是 `<截图 / 日志片段 / 存档 diff>`，文件放 `<证据目录>/<日期>/<事项编号-名字>/`，路径写进 LOG。没证据一律写「代码已实现，待验证」。
- **失败处理**：同一事项连续两次尝试失败，或在它上面已耗 1 小时 → PLAN 标 blocked，LOG 写现象、日志路径、你的猜测，换下一项。不要在一个坑上转圈。
- **每完成一项**：`git commit`，提交信息写明验证状态；新发现的坑追加到 `<坑记录文件>`。
- **省上下文**：长输出先写到 `<证据目录>/logs/` 再让 scout 摘要；反编译文件、大表不要整个读进上下文；给子会话的 brief 自己写清楚，不说「见上文」。
- **需要用户拍板的事**（`<例如资源来源、数值取舍、砍不砍功能、账号和协议>`）：选最保守的默认值继续，并记进 REPORT 的「待你决定」。不要停下来等。

### 绝对不做（按项目填）

- 不碰 `<不许碰的设备：名字或串号>`；只用 `<设备名>`。`<别的项目占用的设备或端口>` 也不用。
- 不 `<清数据 / 卸载 / 重置类命令>`。需要新数据只删 `<具体文件>`；删之前先备份，确认备份文件存在再删。
- 换掉了用户自己的数据（`<存档或配置的位置>`）：先备份并记哈希，停止前逐字节还原，`<共用设备登记表>` 里释放占用。
- 不删 `<受保护的目录和文件>`。不改 `<其他仓库或目录>`。不 `git push`，不发布、不上传任何东西。
- 不改系统设置、不装系统级软件；`<包管理器>` 装进项目目录可以。
- 不开超过两个子会话，不用 `<不许用的模型>` 开子代理（本文件没有授权）。
- 不在 LOG 和 REPORT 里写「应该没问题」：要么有证据，要么写「未验证」。
- `<项目特有的环境规矩，例如某个 shell 下带设备路径的命令要先设什么环境变量>`

### 停止条件（任一满足就调 `ScheduleWakeup` 的 stop）

PLAN 全部 done 或 blocked；额度低于 `<额度阈值>`；连续三次醒来没有任何事项状态变化；本地时间到 `<截止时间>`（「今晚的额外授权」另有说明的除外）。

停止前先还原用户数据（如果动过），再写 `<状态目录>/NIGHT-REPORT.md`，五段，每段要短：
1. 已验证（事项 + 证据路径 + 提交哈希）
2. 已实现未验证（为什么没验上）
3. 阻塞（现象、日志路径、你的猜测、建议用户怎么查）
4. 待你决定（每条给出你选的默认值和备选）
5. 本晚额度消耗（开始和结束各多少）、回来可以直接用的产物路径、所有子会话和子代理的名字和状态

然后提交，停止循环。

### 醒来间隔

有子会话、子代理或后台命令在跑：兜底 1200 秒，靠完成通知唤醒。否则做完一项立刻做下一项，不要为了「检查一下」而醒来。每次调 `ScheduleWakeup` 时 noop 要如实：有事项状态变化才是 false。

## 状态文件格式

`NIGHT-PLAN.md`：

```markdown
# 夜间计划（<日期>，按 NIGHT-RUN.md 执行）

设备：<设备名和连接方式>。不用：<不许碰的设备>。
用户数据：<换没换过；备份位置和哈希；停止前必须还原>。

| # | 优先级 | 状态 | 事项 | 完成标准 | 涉及文件 | 验证方式 |
|---|---|---|---|---|---|---|
| 1 | P1 | in_progress | … | 状态变化可见，重启后仍正确，0 报错 | … | 截图 + 日志 |
| 2 | P2 | pending | … | … | … | 存档 diff |
```

状态只用 pending / in_progress / done / blocked，后面括号里可以补一句（例如「done（另一个按钮的问题见 #6）」）。

`NIGHT-LOG.md`：一行一件事，开头是本地时间。

```markdown
# 夜间日志

- 02:52 第一次醒来：keep-awake 已开；额度 5 小时窗 43%、周 42%；git 基线 <哈希>；设备 <设备名> 在线；无子会话。
- 02:55 计划建立，共 8 项（#1 in_progress）。
- 03:05 #1 done：<看到了什么>；证据 <证据目录>/<日期>/01-<名字>/；提交 <哈希>。
- 04:05 停掉卡住的 scout（后台命令在等标准输入），它的活我已做完；坑已记入 <坑记录文件>。
```
