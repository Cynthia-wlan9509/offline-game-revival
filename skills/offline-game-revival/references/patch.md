# 锚点补丁与重打包

## 1. 补丁点的优先级

按"不修就进不去"→"修了才好玩"排序，不要一上来就做玩法：

1. **启动路径** — 定时器 / 更新检查 / 热更校验，全部短路
2. **登录** — 造本地账号 → 本地回包 → 直接进主界面；断开 socket 连接
3. **网络层** — 所有请求改本地响应
4. **资源校验** — CRC / 完整性检查
5. **存档** — 进度落本地持久化
6. **内容** — 剧情、抽卡、任务等具体玩法

先保证"能进主界面"，再逐项接功能。每一步都要能单独回滚。

## 2. 锚点替换 + 断言

每处改动 = 旧串 → 新串 + `assert`：

```
PAT_OLD = crlf("""function X:OnClick() ... end""")
PAT_NEW = crlf("""function X:OnClick() -- [MARK] ... end""")

assert PAT_OLD in text, "<位置> anchor missing"
text = text.replace(PAT_OLD, PAT_NEW, 1)
```

规则：

- 锚点取**原包里真实存在**的文本，越具体越好（带缩进、带相邻语句）
- 每加一处替换就加一条 `assert`
- 构建后对**生成物**再验一次关键串确实存在
- 统一标记（如 `[OFFLINE-MEMORIAL]` / `@MARK@`），方便一条命令搜出全部改动
- 注意行尾：同一份文件可能是 CRLF 也可能是 LF，锚点匹配要两种都试
- **放行 / 跳过类开关不许硬编码**：模板里写占位符（`bypass = @BYPASS@`），构建期从策略文件渲染，
  并断言取值来源存在。本项目曾因门禁模板里硬编码 `bypass = true`，让"本机授权码校验"静默失效数周
  ——文档写着校验、代码从不执行，谁都没发现。默认值越"宽松"，越要让它显式可查。
- 生成物里要能反查开关取值（构建清单记一条），否则事后无法判断某个包是哪种配置。

## 3. 本地回包

网络层改造的通用骨架：

- 拦截发送函数，按协议号查表返回本地构造的响应
- **离线时网络层会抛异常**，异常沿调用栈打断调用方。所有调用点用 `pcall` 包住，否则症状是"按钮点下去没反应"
- 配置表是懒加载的，离线入口必须等解析完成再进，否则拿到空表
- 响应结构照着**原协议字段**填，宁可字段全填也不要缺——缺字段的报错现场往往离真正原因很远

## 4. 重打包

```
补丁脚本   →  生成改写后的 bundle
构建脚本   →  合并热更资源 + 替换 bundle + 归零相关 CRC  →  未签名 APK
签名       →  zipalign + 签名
```

- 每轮构建换新目录 / 新版本号，**不要覆盖**上一个已验收的包
- 构建后确认产物大小、时间确实变了
- 始终保留一个 known-good 包作为回滚点

## 5. 签名与覆盖安装

- 同一包名必须用**同一签名**，否则覆盖安装失败或要求卸载（丢存档）
- 测试签名与发布签名分开；不要图省事用测试签名盖正式包
- 覆盖安装：

```powershell
adb install -r --no-incremental <candidate.apk>
```

## 6. 把改动留在源里

- 逻辑写在独立脚本模块，主入口负责拼接；不要直接改生成的 bundle
- 临时脚本用完就比对合并或删除，别让 `_tmp` 目录变成"第二套事实源"
- 产物目录、日志目录不进版本库
