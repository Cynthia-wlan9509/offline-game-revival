# 锚点补丁与重打包

## 1. 补丁点的优先级

按"不修就进不去"→"修了才好玩"排序，不要一上来就做玩法：

1. **启动路径** — 定时器 / 更新检查 / 热更校验，全部短路
2. **登录** — 造本地账号 → 本地回包 → 直接进主界面；断开 socket 连接
3. **网络层** — 所有请求改本地响应
4. **资源校验** — CRC / 完整性检查
5. **存档** — 进度落本地持久化
6. **内容** — 剧情、抽卡、任务等具体玩法

先保证"能进主界面"，再逐项接功能。每一步都要能单独回滚。

## 2. 锚点替换 + 断言

每处改动 = 旧串 → 新串 + `assert`：

```
PAT_OLD = crlf("""function X:OnClick() ... end""")
PAT_NEW = crlf("""function X:OnClick() -- [MARK] ... end""")

assert PAT_OLD in text, "<位置> anchor missing"
text = text.replace(PAT_OLD, PAT_NEW, 1)
```

规则：

- 锚点取**原包里真实存在**的文本，越具体越好（带缩进、带相邻语句）
- 每加一处替换就加一条 `assert`
- 构建后对**生成物**再验一次关键串确实存在
- 统一标记（如 `[OFFLINE-MEMORIAL]` / `@MARK@`），方便一条命令搜出全部改动
- 注意行尾：同一份文件可能是 CRLF 也可能是 LF，锚点匹配要两种都试
- **放行 / 跳过类开关不许硬编码**：模板里写占位符（`bypass = @BYPASS@`），构建期从策略文件渲染，
  并断言取值来源存在。本项目曾因门禁模板里硬编码 `bypass = true`，让"本机授权码校验"静默失效数周
  ——文档写着校验、代码从不执行，谁都没发现。默认值越"宽松"，越要让它显式可查。
- 生成物里要能反查开关取值（构建清单记一条），否则事后无法判断某个包是哪种配置。
- **门控要精确到完整编号**：按“编号 ÷ 10”之类的规则推家族，会把相邻编号的变体一起带进补丁路径（实测一个从没测过的变体被当成同族，也执行了补丁）。门控用完整编号的名单，或者加排除名单；评审时把同一家族的所有编号列出来逐个看。
- **改了构建期检查，要用真实的正式构建验一遍**：新检查在开发测试包上都过了，真实的 `--final` 却失败了（检查也作用到了不是 UnityFS 的普通序列化文件上），而外层一个宽泛的 `except Exception` 把断言吞掉，当成「找不到」报了出来。检查只作用于它适用的数据；包裹逻辑里的宽泛 except 要把自己的断言重新抛出；改完后正式包和开发包各打一次，装机冷启动。（案例 A 2026-10-18）

## 3. 本地回包

网络层改造的通用骨架：

- 拦截发送函数，按协议号查表返回本地构造的响应
- **离线时网络层会抛异常**，异常沿调用栈打断调用方。所有调用点用 `pcall` 包住，否则症状是"按钮点下去没反应"
- 配置表是懒加载的，离线入口必须等解析完成再进，否则拿到空表
- 响应结构照着**原协议字段**填，宁可字段全填也不要缺——缺字段的报错现场往往离真正原因很远

- **补离线缺口时，尽量保持原版流程**（案例 A 2026-11-01 更正）：曾把日常宝箱改成领取时直接打开、直接给经验，玩家反而以为宝箱丢了。后来改回原版做法（宝箱进背包、打开才得经验），并在领取时加一句提示。宁可加提示，也别替玩家自动完成原版要他自己做的步骤。
- **付费入口统一在汇合函数里拦**（案例 B 2026-10-19）：首充、月卡、礼包、通行证、客服、兑换码、分享等入口很多，逐个改容易漏。让 scout 盘点入口，找到所有真钱购买都会经过的那个函数，在那里加锚点补丁，统一弹「离线版暂不支持」；不经过它的入口（充值页签、客服、用户中心、兑换码、分享）另加同样的拦截；免费的广告奖励保留。补丁里写在一行的提示代码不要带行尾 `//` 注释，否则会把后面的大括号也注释掉。

## 4. 重打包

```
补丁脚本   →  生成改写后的 bundle
构建脚本   →  合并热更资源 + 替换 bundle + 归零相关 CRC  →  未签名 APK
签名       →  zipalign + 签名
```

- 每轮构建换新目录 / 新版本号，**不要覆盖**上一个已验收的包
- 构建后确认产物大小、时间确实变了
- 始终保留一个 known-good 包作为回滚点
- **剥资源后同步清理 AssetBundleManifest 的依赖**：保留下来的包如果在总清单里依赖被剥掉的包，Unity 会整包返回 null（见 `pitfalls.md`「留下的资源包在总清单里依赖已剥掉的包」）。
- **查和包字节有关的崩溃，用「换包 + 重签」小脚本二分**：把手工生成的 bundle 替换进已有的正式包 APK，重新对齐、签名，装机冷启动，看一行 Lua 加载之后才会出现的日志。每个实验约 1 分钟，不用跑完整构建。再配一个自写的最小 UnityFS 读写器（能指定块大小、压缩方式、精确的压缩字节数），一次只改一块、一个字段做对照（案例 A 就是这样找到「压缩后恰好等于原始大小」那个崩溃的，见 `pitfalls.md`）。

- **UnityPy 重写 serialized 文件后体积明显变小**（案例 C：一个 prefab 从 6700 字节变成 3552 字节），多半是丢了原文件的头部布局和对齐填充。要逐对象对比原文件和新文件的头部及对象元数据，不一致就补齐成原来的布局再放进包。改贴图时用游戏自带的字体渲染文字，再编码回原格式（如 ETC2）。真机上看到新内容才算数。

## 5. 签名与覆盖安装

- 同一包名必须用**同一签名**，否则覆盖安装失败或要求卸载（丢存档）
- 测试签名与发布签名分开；不要图省事用测试签名盖正式包
- 覆盖安装：

```powershell
adb install -r --no-incremental <candidate.apk>
```

### 改包名，和官方版并排安装（案例 C 2026-11-01）

包名相同、签名不同时，系统会直接拒装。想让纪念版和官方版共存，构建期要改三处：
1. 二进制清单（AXML）：重建 UTF-16 字符串池，把包名连同所有带包名前缀的串一起换掉（权限、provider、fileprovider、推送用的 C2D_MESSAGE 等，用一张后缀表枚举）。更新块大小和文件大小，断言全部替换到位；类名不动。
2. `resources.arsc` 的 package 块名字（128 个 UTF-16 字符的定长字段）。漏了它，包能装上，但一启动就找不到资源（见 `playtest.md` 测试分身那一段）。
3. 桌面名在 arsc 的 UTF-8 字符串池里，可以原地替换，但新名字不能比原名长。
- 再 grep 一遍 Java / smali 里写死的带引号包名；工具脚本里写死的包名改成读环境变量。
- 存档目录会跟着变成 `Android/data/<新包名>/`，旧包的存档不会自动带过去，安装说明要同步改。
- 验证：用 `aapt dump badging` 看包名和桌面名；模拟器上新旧两个包同时装着，新包能进主界面、能读写存档。
- Laya / conch 的包也一样要改资源表（案例 B 2026-10-29）：Android 9 以后找资源时会比对 `resources.arsc` 里的 package 名，只改清单就找不到资源。脚本里写死的私有目录路径用占位符（如 `@PKG@`），构建时替换，并断言旧包名不再出现。本机码如果取的是 `ANDROID_ID`（按签名证书区分），换包名后不变，旧授权码照样能用；存档要迁移。

## 7. 发包前对脚本做一层加密（可选）

离线逻辑若原样拼进脚本包（如 `main.bytes`），解包就能读到全部服务端逻辑和中文注释。没有 .NET SDK 改不了 C# 程序集时，可以走纯 Lua 加密：打包时把离线逻辑加密成一段字符串，只留一小段引导码，运行时解密后用 `loadstring` 加载（游戏自己就用 `loadstring`）。只挡随手解包，挡不住铁心逆向。注意：每个模块要包在 `do...end` 里避免超 200 局部变量上限；留一个 `--no-enc` 开关便于调试；打包后 grep 确认搜不到模块名明文。**加密后必须真机冷启动验收**（启动速度、是否正常加载）。

- 逻辑写在独立脚本模块，主入口负责拼接；不要直接改生成的 bundle
- 临时脚本用完就比对合并或删除，别让 `_tmp` 目录变成"第二套事实源"
- 产物目录、日志目录不进版本库
