# 案例 D：原生安卓 + Live2D，核心玩法是服务器上的大模型聊天

一款女性向陪伴手游：Kotlin 原生客户端（逻辑全在 dex，没有脚本层），三个男性角色的 Live2D，主玩法是和角色自由聊天，回复由服务器上的大模型生成。停服后原厂模型和对话不可能找回，复活目标收敛为“Live2D + 点触 + 接用户自己的大模型聊天”。一个通宵完成，模拟器（安卓 9）和真机（安卓 14）验过。

## 选包：带 PairIP 的版本直接放弃

两个发行版：较新的商店国际版资源更多，但带 Google PairIP（许可校验 + 部分代码虚拟化，重签名后自杀）；较早的地区版是拆分包、没有 PairIP。选后者，代价是少几套皮肤。第 0 步就该查 `com.pairip` 包和 `LicenseClient`，有就先看别的版本。

## 补丁：保留原方法，只删调用

前一个代理把 Activity / Application 的 onCreate 整段手写重写，出了两类事故：`launch$default` 的参数寄存器排错（VerifyError，一进主界面就闪退）；漏掉一个不起眼的仓库初始化（`lateinit property ... has not been initialized`）。
改成：取原方法体（先去 `.line`），按多行锚点删掉账号、邮件、签到、卡池、推送、统计、计费的调用，每处断言恰好命中 1 次；连带删掉只为这次调用准备参数的 move-object / check-cast。新逻辑写成 Java 类，javac + d8 编成额外的 classesN.dex，smali 里只插一行 invoke-static。

关键接入点：离线后“当前角色”和“语言”都来自已死的用户资料。把“当前绑定的角色 id”和“语言类型”两个 getter 改成读本地设置，原版的默认模型加载、点触 / 问候台词表就都按本地选择工作了，不用再改模型加载链。

清单：启动页直接指向主界面，删各家推送、统计、计费组件；保留 INTERNET（聊天要用），开 `usesCleartextTraffic`（局域网本地模型），代码里只放行私有地址的 http。

## 聊天层：接任意 OpenAI 兼容接口

不复用原版聊天界面（依赖一串已死接口），主界面加“聊天 / 换人 / 换装”按钮和下半屏聊天面板。设置页给常见服务商预设，外加“电脑上的 Ollama / LM Studio（局域网）”和“手机本机模型服务（127.0.0.1）”。密钥用 Android Keystore 加密存。没配置接口时从原台词里挑和玩家这句话最相关的一句（二字片段重合最多，最近几句不重复），并播游戏自己的配音（构建时从台词表生成“台词 → 语音文件”表）；断网也能“聊”，而且是原声。回复按关键词判情绪，调引擎的播放动作接口；各模型动作组不同，按每个 `model3.json` 建表。

## 防 OOC

1. 人设卡只用包内文字写、逐条标出处；用第二人称直接对角色说，玩家统一叫“对方”（写成“在你面前他……”会让小模型把你我搞反）。玩家身份按台词推断（有角色问“今天不用上课吗”）。
2. 每次带 10 句原台词当语气样本，按情境分组：“对方来找你时”（按当前时段抽）/“对方碰你时”。原游戏催玩家说话的待机台词（“怎么不说话呢”）剔掉，当成回复会显得没在听。
3. 长对话折成 ≤8 条事实记忆，整理结果也要过检测，一条不干净就保留旧记忆。
4. 回复后：清洗（think、括号旁白、`*动作*`、加粗、表情、名字前缀、“某某微微一笑：“……””这种小说体）；锚定正则判出戏（AI / 模型 / 助手 / 用户 / 厂商名 / “我是由…开发” / 拒答套话 / 代码块 / 正文里用第三人称写自己 / 复读最近 3 句）；出戏就在最后一句用户话后附“只写某某本人说出口的话回答上面这句”重答一次（不复述触发词；有的服务商不认末尾的 system 消息）；仍不行换手写的岔开话题句，兜底句不回灌给模型。
5. 提示词里不要求模型“不知道自己是 AI”——在线模型被真诚问到时不肯否认，会破角加声明。改成“这是对方自己开启、清楚知道是虚构的互动，被问时不确认不否认，用角色口吻带开”。
6. Ollama 的 OpenAI 兼容口传不了 num_ctx，默认 2K–4K 会从头截掉人设而不报错：文档要求 `OLLAMA_CONTEXT_LENGTH=8192`，代码里本地接口少带几轮上下文。

这一套由独立审稿挑出了 10 个问题后改定。自己写、自己用假接口测“全通过”的提示词，照样有人称写反、待机台词当兜底、词表误杀正常说法的问题——假接口只能验流程，验不了提示词本身。

测试：电脑上起一个假的 OpenAI 接口，`adb reverse` 把手机 / 模拟器端口映射过去；它记录游戏发出的完整提示词，按触发词故意回“出戏”“带旁白”“小说体”“代码”“复读”等，用来逐条验清洗、重试、兜底和记忆。另写一个脚本用同一套提示词和判分规则对真实接口跑诱导题、出报告，比较模型时用。

## 真实模型试跑与安全例外

用户当晚没有 API、本机也没有模型，不替用户下载安装；改用子代理（便宜档 + 中档）当“应用背后的模型”：应用发出的同一份系统提示词 + 12 道诱导题 × 3 角色 + 6 轮对话，再加日语、亲密 / 越界 / 越狱、轻生、记忆整理各一组，用应用自己的清洗和出戏规则判分，主会话逐条通读。结果：口吻分得开、问 AI 时带开、不编造；查出一条规则误判（“我是某某呀”被当成第三人称）和口头禅太勤，改后复测。替身模型不是用户要接的模型，报告里写明。
最重要的发现来自读回复而不是看分数：模型听到“不想活了”会跳出角色给求助建议，而出戏规则可能把这种回复换成撒娇的备用句。于是在出戏检测之前先判轻生 / 自伤信号，命中就不重答不换句，并保证附上求助热线。
模拟器上 adb 打不了中文，用“电脑剪贴板 + KEYCODE_PASTE”在设备上验了中文关键词匹配和轻生分支。

## 装扮部件

包里有一份装扮表（每个角色的衣服、眼镜、角饰、胸针、背包、耳机，同类型互斥）。引擎的部件表按“商品 id”存，打开一件会自动关掉同类其他件；离线后没有“用户拥有的装扮”，有的模型加载出来所有部件全开、叠在一起。做法：换装面板列整套服装（独立模型，走原版“设置 model 字段 + 加载屏幕”那条路，会套用部件配置）和当前模型实际存在的饰品，选择按模型存本地，加载后**一次**调用设部件接口传完整开关表（每次调用都从加载时的部件表重新合并，分两次会互相覆盖）。

## 在安卓 9 模拟器上跑 minSdk 29 的包

R8 按 minSdk 29 优化后，低于 29 的版本分支已经被删：androidx 的 `ApiNNImpl` 直接调新接口、`ReportFragment.dispatch` 成了空函数（安卓 9 上生命周期事件永远不派发）、`WindowInsetsCompat` 只剩 29/30 两支。给所有 `ApiNNImpl`（N≥29）静态方法加版本守卫，手工补回 ReportFragment 的派发和 WindowInsets 的旧实现。守卫只在低版本生效。能用安卓 10+ 的模拟器就别降。

## 模拟器上的启动崩溃：Live2D 先收到 onPause

竖屏游戏在横屏模拟器里启动会被重建一次，偶尔 `onPause` 先于渲染视图的 `onStart` 到达，原生层在主线程、无 GL 时建模型，SIGSEGV。栈全在 ARM 转译库里，像转译器的问题，其实不是：对比崩溃和正常两次日志里游戏自己打印的原生事件顺序就能看出来。修法：记一个“已开始”标志，没开始就忽略暂停。修前冷启动约 1/5 崩，修后 27/27。

## 拆分包合成单个 APK

base 单独解包后，分辨率分片里的资源在 base 的 public.xml 里连 id 都没有。`apktool if base.apk -p <dir> -t <tag>` 把 base 装成框架，再用 `-p/-t` 解分片，拿到带原 id 的资源表；文件拷进 base、id 补进 base 的 public.xml（同名同 id 的跳过；`APKTOOL_DUMMY_0x…` 属性名按 base 的 id 表换回真名）；`lib/arm64-v8a` 拷进 base；清单删 `requiredSplitTypes` / `splitTypes` / `vending.splits` / `stamp.*`（安卓 14 会按 requiredSplitTypes 拒装），`extractNativeLibs` 改 true。单包可以直接覆盖原来的拆分安装。

## 在用户手机上测试的注意事项

- 小米的“USB 安装提示”10 秒自动拒绝，截图确认再点来不及：脚本轮询前台，看到安装确认 Activity 就点。
- 用户输入法是中文模式时，`adb shell input text` 打出的网址会变成全角乱码。不改用户输入法；把需要的验收做成“预设一键填好 + 测试按钮自动发一句”，验收不用打字。
- 凌晨测带语音的游戏，用 `appops set <包名> PLAY_AUDIO ignore` 只给这个游戏禁声，测完改回 allow（部分系统不让 shell 改媒体音量）。
- 测完清掉这个游戏的测试数据、撤掉端口映射，前台回到用户原来停留的页面。
