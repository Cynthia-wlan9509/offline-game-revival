## 游戏特征

- 包名 `com.example.game`（测试包 `...probe`），Unity + Lua
- 1443 个 TextAsset，DES-CBC 加密，`key == IV == <8 字节密钥>`
- Lua bundle 头部有 8 个 `0x00`，**原包如此，不是损坏**
- CRC 实际读 `assets/AssetBundles/Android/AssetDatabase.manifest`
- `DataTableMgr` 懒加载，离线入口必须等 `ParseDataTable end`
- 离线时 `MsgManager.sendData` 抛 `NullReferenceException`，必须 `pcall` 包住调用方
- 离线素材在 `04-工作区\work\phone_hot_2023`，由 `build_apk_v2.py` 合并
- 真机：某品牌 Android 14 arm64 真机

## 构建链路

```powershell
cd <项目根>
python tools\patch_offline.py     # 生成 build\luascript.offline.bundle，含锚点断言
python tools\build_apk_v2.py      # 合并热更资源 + 替换 bundle + 归零 CRC
# 再用发布签名 + zipalign，产物放 out_<版本>\
```

`tools\cycle.ps1` 与 `tools\build_apk.py` 是**旧流程**，不要作为权威构建方式。

## 上一阶段的定位与继承关系

`<工作区>\<上一阶段目录>\`（4.2 GB / 1805 文件）是**只读禁区**，但必须理解它与本阶段的关系：

**它的路线**：运行时注入（Frida Gadget）。这条路线**未成功**——上一阶段自己的交接文档承认卡在"Gadget 自动脚本模式"，并且它列的验收标准之一就是"不需要 Frida"。它做到的是"跳过登录"：hook 掉 `StartSocketConnect` / `sendData` 后强跳 `ShowLuaStage("MainStage")`；进主界面后点主城会报 `_mainStoryWorldMapView` 为空的 Lua 异常。**那不是绕过登录。**

**它真正的、不可替代的产出是侦察结论**：

| 产出 | 用途 |
|---|---|
| Lua 密钥（运行时读 `LuaRuntimeConfig.LuaScriptKey()`） | 解锁 1443 个加密 TextAsset |
| `offline_analysis.md` 函数级靶点清单 | 直接指出要改哪些文件 |
| `login_protocol_schema.json`、`rpc_entrypoints.json`、`lua_network_hits.json` | 本地回包照字段填的依据 |
| 解码后的 TextAsset 清单 | 索引基础 |

**它的最大教训**：上一阶段**误判了自己的阻塞点**并把时间花在了上面。后续阶段读它留下的 logcat 才发现，卡点不是 Gadget，而是另一个 8 秒后盖住画面的强制跳转，且该跳转的触发条件（`sendCount >= 3`）在整份日志里永远不可能满足——即使 Gadget 调通也进不去。

**⚠️ 隐藏耦合（重建链路时是雷）**：`tools\build_apk_v2.py` 的构建基准是上一阶段的阶段包，不是原包：

```python
SRC_APK = r"<工作区>\<上一阶段目录>\<阶段目录>_2026-09-23\案例A-离线阶段包-阶段可玩版.apk"
```

也就是说**当前产物是叠在上一阶段的阶段包之上的**。上一阶段当年对 13 个 AssetBundle 头部 8 字节填充做的"修复"已经混进了这个基准包，而本阶段文档里另有"`luascript` 头部的 8 个 `0x00` 是原包如此、不是损坏"的说法。

**2026-10-13 已核对**：直接读原始安装包，2355 个资源包里 2354 个开头带 8 个零（唯一例外是清单包 `Android`），全部能正常加载。所以"原包如此"是对的，那 8 个字节不需要修复。上一阶段的阶段包里那 13 个被"修复"过的包和原包差在哪，还没有逐个比对——脱离阶段包从原包重建前要比一次。

**无论阶段包是否还在 03 目录，构建链路都依赖它。删它就等于断掉可复现性。**
## 本项目沉淀的通用教训

1. **Frida 路线失败 → 打包期改 Lua 成功。** 运行时注入依赖外部环境，脚本层改写才是交付形态。
2. **CRC 猜错一轮。** 先改 `luascript.manifest` 无效，真机日志显示游戏读的是 `AssetDatabase.manifest`。这类问题看日志比看代码快。
3. **时机问题。** 补丁逻辑正确但因"进得太早"失败，症状像逻辑 bug，实际是时序问题。
4. **文档漂移是真实成本。** README 一度同时保留旧哈希、旧结论和旧构建脚本，导致后续 Agent 判断错误。
5. **产物清理要谨慎。** 可再生的构建产物删了不心疼，但**手工打在产物里的改动**会永久丢失；清理前必须先确认没有"只活在产物里"的补丁。
