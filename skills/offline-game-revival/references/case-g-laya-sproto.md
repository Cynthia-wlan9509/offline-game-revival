# 案例 G：LayaAir Conch + 长连接 sproto 协议的剧情养成手游（整包在手，一路做到全部养成系统）

2026-11-09 起。引擎和案例 B 是同一套（LayaAir Conch 外壳 + JS），先读 `case-b-laya-native.md`，这里只记不一样的地方和新踩的坑。用安卓 9 的模拟器测。

## 第一天的结论

- 台服整包 APK：`bundle.js` 约 6.6 MB、约 2.8 万个资源文件，不是微端，本体全在。预估 5～8 小时到能录演示；最没底的是登录后服务端下发的那一整包玩家数据，只能从客户端代码倒推。
- 当天走到：登录页 → 选服 → 创角 → 序章 → 主城 → 主线第一节。
- **按配置引用逐类对资源**（让游戏自己去数，不凭文件夹）：界面图集 142/142、22 章剧情全在、卡面 217/217、服装 2322/2322、角色骨骼 20/20、语音 952/954。缺的只有服务端上的数值、抽卡概率、活动排期、商店上下架，这些自造的标【自造】、推断的标【推断】。

## 协议层

- 逻辑服和网关是两条 WebSocket，数据用 sproto 编码。**协议定义文件是 msgpack 格式，里面有 400 多个请求的回包字段表**，构建期把它转成 schema 注入，省掉大量倒推。
- 替换点在 `Network` 原型上：假的服务器列表、假的 logicSocket / gateSocket（不给的话创角会被 `logicSocket == null` 拦住）、发送改走本地处理函数；回包经客户端的通知函数分发，推送走统一的 push。客户端只读它用到的字段，所以可以直接回比 schema 更新的结构。
- 离线模块在构建时拼进 `bundle.js` 的闭包里（`new Main();` 之前），能直接用闭包里的类（引导管理、界面管理、配置、数据管理），这些类不在 window 上，从外面拿不到。`bundle.zip` 也要重打。
- **启动死循环**：file:// 下加载器解压 `bundle.zip` 会无限重载，JS 内存涨到 689 MB 被杀；原版 zip 一样，不是补丁的错。启动脚本改成直接加载两份 js。渠道配置请求由 smali 改成返回本地文件；平台分发函数覆盖成本地渠道。
- 模块按编号前缀排序（网络、登录、章节、奖励、战斗、……），一个系统一个文件；拼接顺序见 `pitfalls.md`「离线模块按文件名顺序拼接」。

## 做法上值得照抄的几条

- **先分清哪些在客户端算、哪些在服务端算**：换装评分、互动小游戏、战斗表现在客户端，服务端只管买卖和结算；战斗客户端不会自己上报，必须由服务端推进，所以离线版固定“赢 + 扣体力”。过关奖励原本在服务端、已经随服务器丢了，界面“恭喜获得”是空的：自己定一份奖励并标【自造】。
- **引导的隐性前提**：引导遮罩挡住了购买按钮，说明原版玩家走到这一步时手里已经有这件东西。配置里找不到发放来源，就是原版服务端在进关卡时发的：在进入那一关时补发。
- **别凭字段顺序猜数值方向，用界面文案核**：抽卡界面写着“再买 10 次必出最高档”，而我最初按奖池字段顺序写成了保中档，点开界面才发现。
- **战斗表现只在一方倒下时才恢复界面**：服务端一个回合就回结算，界面会卡住不出按钮。循环交换到一方倒下为止（加个 200 次的保护）。
- **收获发的是种子本身**：种子表里的奖励字段就是种子，作物是同名的另一件物品，按名字查。
- **付费选项**：剧情选项的结构里有一项是花费（道具 + 数量），要真扣；不扣的话玩家点了没反应还显示不够。
- **多人引导没意义**：加入公会的新手引导在单机里永远做不完。用一个定时监视器：引导在进行且打开了公会类界面，就直接结束引导并关界面。
- **充值才有的东西怎么给**：会员等级只能靠充值涨，而会员礼包本身是用游戏币买的。做法是让玩法也能涨会员经验（花游戏币、每天首登），首充、月卡、直购类按会员等级寄邮件；会员等级要在“取玩家信息”那一步就算好（见 `pitfalls.md`「回包和推送的先后」）。
- **一次开三四个 worker，各写一个独立文件、不碰构建、不上设备**，主会话审代码、统一连线（任务计数这类跨模块的）、上模拟器点一遍。worker 会顺手发现别的模块的 bug（本例：小节奖励没人发、未知奖励类型被静默丢掉），由主会话判断后修。

## 自动推进脚本（比人工点快一个数量级）

- 真实 adb 点击 + 调试通道读状态：当前引导指向哪、有哪些层、顶层是什么。**引导的高亮位置要读引导特效控件的坐标，别读整个界面**（后者是整屏）。
- 卡住就是新缺口。每遇到一种卡点就教脚本一条规则：关奖励弹窗、点空白处关闭、进剧情先点“跳过”（注意“快进”状态换段落会被重置，不能只开一次）、遇到选项点第一项、遇到确认框点确定、战斗界面按钮优先于背后的剧情层、有成功率的升阶最多试 15 次。脚本遇到“进度条/下一节”要按界面指示点，不要按节点编号取最大的（编号没有顺序）。
- 点之前先确认前台是自己的游戏：这次有一轮脚本全程没点到东西，是另一个会话把别的游戏推到了前台。
- 脚本和手工查询共用一条调试通道时会串，见 `pitfalls.md`。

## 正式包

- 清单里去掉联网权限（改名，断言只命中 1 次），正式包跳过调试模块，自检确认没有调试钩子也没有联网权限。
- 两处 smali：全局未捕获异常处理器（在应用入口 `attachBaseContext` 的 `super` 之后安装）和网卡枚举返回 null 时直接返回空串。前一处见 `pitfalls.md`「去掉 INTERNET 后，推送 / 统计 SDK …」，后一处和案例 B 是同一个坑。
- 玩家嫌满屏水印烦：改成头像下方两行小字（本机码、序号），设置里另开一个“壁纸”区，进去没有水印，可把卡面原图存到相册，存下来的文件和原图逐字节一致。

## 玩家反馈批里出现的问题（都已写进 pitfalls）

默认回空包的副作用、领奖报拟声词错误、显示 100% 仍失败、活动列表一项坏掉后面全不出现、虚拟玩家衣服不全被投诉、简体模式下按钮点不了、章节分支里重复出现同一段剧情（两条分支共用同一批剧情任务，用实际的章节代码把每条分支按小节顺序跑一遍就能看出重复）。
