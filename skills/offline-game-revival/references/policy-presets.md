# 单机化产品默认策略预设（开局可一键勾选）

以下策略都在实战项目里用过，建议在开局 `KICKOFF-AUTH.md` 中直接拍板，避免推进中途反复停下询问。

## 1. 1:1 原版 UI 与真实性底线（D0）

- **锁死 1:1 原版 UI 与真协议回包**：坚持构造客户端真实期望的协议结构复用原厂 UI 与 Handler；未获用户明确拍板，**严禁私自写自绘壳或合成假界面**（返工成本极高，仅作极端兜底）。
- **写接口严禁默认成功兜底**：未实现协议仅允许只读查询安全兜底不断线；任何消耗/发奖/写档协议未实现时必须显式拒签并记日志，杜绝“表面领取成功、冷启数据消失”。

## 2. 可玩优先原则（D1 规则 + `[重建]` 登记表）

当服务端独有的掉落概率、商店刷新权重、活动期次或合成配方在客户端表里查不到时，按以下顺序执行，**命中即停、不为此阻塞**：
1. 原配置表/反编译代码能直接读到规则 → 100% 照用；
2. 原表有部分权重/成本/上限 → 按已知字段实现，缺失部分取最简合理值；
3. 完全无依据 → 参考同类已实现系统定合理规则。

所有非原服确证规则/缺失算法统一标注 **`[重建]`** 并在 `交接/本地规则登记.md` 追加一行（规则名、涉及系统、依据配置、一句话说明），交付时如实透明告知玩家。

## 3. 离线商业化与付费礼包统一方案（代金券模式）

- **彻底移除真实支付与第三方 SDK**，0 外网请求（纯包内方案直接移除 `INTERNET` 权限）；
- **统一采用游戏原生代金券/银票**（若原包无此货币则定义专用本地代金券）按原价比例（如 `1 元 = 100 代金券` 或按原表定价字段）真实结算；
- **硬性事务要求**：校验余额 → 扣款 → 发全套原商品及附带奖励 → 同步增加 VIP 经验与累充/特权进度 → 写带 `tx_key` 幂等键的购买记录，**必须在同一原子事务内完成**，失败全回滚、冷启动防重复、0 余额必须拒付；
- 正式档是否发开局启航代金券 / 兑换码，在 `KICKOFF-AUTH.md` 开局一次性约定。

## 4. 多人玩法与本地 AI 对手策略

- **PVP / 排行榜 / 竞技场 / 跨服 / 公会**：生成本地 AI 机器人对手与本地榜单，**对手强度必须随玩家等级/战力/排名成曲线增长**（高排名必须真打不过，切忌固定低战力导致必胜无趣）；
- **纯联机聊天**：默认安全隐藏或可选拟真 AI 活服生态（支持 `/ai hot | normal | off` 三档切换，默认不干扰安静单机体验）；
- **缺图/坏资源旧活动或“开发中”占位页**：果断关闭入口并登记原因，绝不留白屏或点击崩溃入口；年月表（`sign_YYYYMM`）跨年必须设循环/默认兜底。

## 5. 单机体验减负（QoL）与存档安全

- **收益倍率开关**：只调掉落/经验/货币倍率（如默认 1× 还原或可选 3×–6×），**绝不魔改原版怪物强度与战斗公式**；
- **轻量减负**：按需增加自动推图、日常/成就一键领取、战斗倍速、多槽位本地备份、防篡改导入导出存档码；
- **GM 纯净隔离**：
  - 正式包默认纯净无 GM 入口（或采用隐藏聊天/兑换码口令唤起，不污染正常界面与自然档）；
  - 测试期用 GM / 虚拟时钟造的档一律标记 `gmTainted`，永不转为正式档，操作前后以 SHA-256 守卫用户正式档。
